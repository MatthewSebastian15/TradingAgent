# PHASE 3 — Chart & Price, Technical Entry Quality, News Impact, dan Catalyst Intelligence

## 1. Tujuan Phase 3

Phase 3 meningkatkan kualitas analisis dari sisi:

- Pergerakan harga
- Data OHLC
- Technical entry timing
- News impact
- Catalyst positif/negatif
- Analyst recommendation trend

Phase ini hanya boleh dimulai setelah Phase 1 dan Phase 2 stabil. Alasannya sederhana: technical dan news harus menjadi pelengkap keputusan fundamental, bukan panggung utama untuk ramalan berbumbu candlestick.

---

## 2. Hasil Akhir yang Harus Dicapai

Setelah Phase 3 selesai:

1. Tab **Chart & Price** menampilkan chart harga yang lebih detail.
2. Chart menampilkan data open, high, low, close, adjusted close, dan volume.
3. Tooltip chart lengkap.
4. Technical Entry Quality tersedia.
5. Tab **News** tidak hanya menampilkan daftar berita, tetapi juga impact scoring.
6. Berita dipisahkan menjadi high-impact, positive catalyst, negative catalyst, dan full news list.
7. Analyst recommendation trend tampil jika tersedia dari Finnhub.
8. HTML preview dan PDF export memiliki ringkasan chart dan news.

---

## 3. Prinsip Sinkronisasi Phase 3

| Prinsip | Detail |
|---|---|
| Chart tidak boleh merusak existing price flow | Jika chart existing sudah ada, extend, jangan rewrite total tanpa alasan. |

# 6. Detail Feature 1 — Price Chart with OHLC Detail

## 6.1 Tujuan

Meningkatkan chart harga agar tidak hanya menampilkan garis harga sederhana, tetapi juga informasi OHLC lengkap.

## 6.2 Data Wajib

| Field | Keterangan |
|---|---|
| `date` | Tanggal trading |
| `open` | Harga pembukaan |
| `high` | Harga tertinggi |
| `low` | Harga terendah |
| `close` | Harga penutupan |
| `adjusted_close` | Harga penutupan disesuaikan jika tersedia |
| `volume` | Volume transaksi |

## 6.3 Window Logic

Chart harus mengikuti window analisis yang diminta user.

Contoh aturan:

| Request Window | Data yang Ditampilkan |
|---|---|
| 1 bulan | Sekitar 60 trading/calendar days ke belakang sesuai konfigurasi project |
| 3 bulan | Sekitar 90-120 days sesuai konfigurasi |
| 6 bulan | Sekitar 180 days |
| 1 tahun | Sekitar 365 days |
| Default | Gunakan default project existing |

Jangan hardcode jika project sudah punya config window. Gunakan config existing.

## 6.4 Tooltip Requirement

Tooltip chart harus menampilkan:

```text
Date
Open
High
Low
Close
Volume
```

Jika adjusted close tersedia, boleh ditampilkan:

```text
Adjusted Close
```

## 6.5 Axis Requirement

| Axis | Requirement |
|---|---|
| X Axis | Tanggal, format readable |
| Y Axis | Harga, dengan konteks currency |
| Volume | Bisa overlay atau chart bawah jika UI mendukung |
| Tooltip | Tidak boleh overlap atau terlalu panjang |

## 6.6 Color Rule

| Kondisi | Warna |
|---|---|
| Close > previous close | Green |
| Close < previous close | Red |
| Close = previous close | Neutral |

Jika chart library existing punya style tertentu, ikuti style existing tetapi tetap pertahankan logika warna.

# 7. Detail Feature 2 — Price Performance Summary

## 7.1 Tujuan

Memberi ringkasan performa harga selama window yang dipilih.

## 7.2 Metrics

| Metric | Formula |
|---|---|
| Period Return % | `(latest_close - first_close) / first_close * 100` |
| Period High | Max high dalam periode |
| Period Low | Min low dalam periode |
| Max Drawdown % | Drawdown terbesar dari peak ke trough |
| Average Volume | Average volume selama periode |
| Volume Trend | Latest volume vs average volume |

## 7.3 Output Contract

```json
{
  "price_performance": {
    "period_return_percent": 5.2,
    "period_high": 9800,
    "period_low": 9100,
    "max_drawdown_percent": -8.4,
    "average_volume": 11000000,
    "latest_volume": 12000000,
    "volume_trend": "above_average",
    "performance_label": "positive"
  }
}
```

## 7.4 Frontend Requirements

| Requirement | Detail |
|---|---|
| Summary cards | Return, high, low, drawdown |
| Percent format | Return dan drawdown pakai `%` |
| Currency | High/low pakai currency |
| Volume | Format readable, contoh `12.0M` |
| Missing data | Tampilkan `N/A` |

# 8. Detail Feature 3 — Technical Entry Quality

## 8.1 Tujuan

Menilai apakah harga saat ini menarik untuk entry berdasarkan teknikal.

## 8.2 Indicators

| Indicator | Tujuan |
|---|---|
| SMA 20 | Short-term trend |
| SMA 50 | Medium-term trend |
| SMA 200 | Long-term trend jika data cukup |
| RSI | Overbought/oversold |
| MACD | Momentum |
| ATR | Volatility/risk range |
| Support | Area harga bawah terdekat |
| Resistance | Area harga atas terdekat |
| Volume Trend | Konfirmasi pergerakan |

## 8.3 Entry Quality Label

| Label | Kondisi Umum |
|---|---|
| Good | Trend mendukung, RSI sehat, risk/reward menarik |
| Neutral | Sinyal campuran atau harga dekat fair area |
| Risky | Overbought, breakdown, volatility tinggi, atau harga dekat resistance |
| N/A | Data harga tidak cukup |

## 8.4 Rules

| Rule | Detail |
|---|---|
| Jangan membuat sinyal trading absolut | Entry quality hanya quality label, bukan jaminan profit |
| Gunakan data window yang cukup | RSI/MACD butuh data historis cukup |
| Jika data kurang | Tampilkan `N/A` dengan alasan |
| Support/resistance sederhana boleh | Gunakan swing high/low atau rolling min/max jika belum ada logic kompleks |

## 8.5 Output Contract

```json
{

    "entry_quality": "neutral",
    "trend": "uptrend",

    "rsi_signal": "neutral",

    "macd_signal": "bullish",

    "sma_50": 9100,
    "sma_200": 8700,
    "support": 9200,
    "resistance": 10000,

      "Price is above short-term moving average",

      "status": "complete",
      "missing_fields": []
    }
  }
}
```

# 9. Detail Feature 4 — News Impact Scoring

## 9.1 Tujuan

Membuat tab News lebih berguna dengan menilai materialitas berita.

Tidak semua berita penting. Sebagian berita hanya limbah SEO yang diberi tanggal publikasi. Sistem harus bisa memprioritaskan berita yang benar-benar relevan.

## 9.2 Data News yang Disimpan

| Field | Keterangan |
|---|---|
| title | Judul berita |
| url | Link berita |
| source | Sumber/vendor |
| published_at | Tanggal publikasi |
| summary | Ringkasan pendek |
| sentiment | positive / neutral / negative |
| relevance_score | 0-100 |
| recency_score | 0-100 |
| materiality_score | 0-100 |
| impact | high / medium / low |

## 9.3 Scoring Logic

| Component | Bobot Contoh |
|---|---|
| Relevance | 35% |
| Recency | 25% |
| Sentiment strength | 20% |
| Source confidence | 10% |
| Keyword/materiality | 10% |

Bobot bisa disesuaikan, tetapi harus terdokumentasi.

## 9.4 Material Keywords

Contoh keyword yang meningkatkan materiality:

| Category | Keywords |
|---|---|
| Earnings | earnings, profit, revenue, margin, guidance |
| Dividend | dividend, payout, distribution |
| Corporate action | merger, acquisition, buyback, rights issue |
| Legal/regulatory | investigation, sanction, regulation, lawsuit |
| Management | CEO, CFO, resignation, appointment |
| Macro/sector | interest rate, commodity price, policy |

## 9.5 Dedup Rules

| Rule | Detail |
|---|---|
| Same URL | Ambil satu |
| Same normalized title | Ambil satu |
| Same source and same title | Ambil satu |
| Similar title | Optional fuzzy match |
| Duplicate vendor result | Merge metadata jika perlu |

## 9.6 Output Contract

```json
{
  "news_impact": {
    "overall_sentiment": "positive",
    "sentiment_score": 68,
    "high_impact_news": [
      {
        "title": "Example headline",
        "source": "MarketAux",
        "published_at": "2026-01-15",
        "sentiment": "positive",
        "impact": "high",
        "relevance_score": 92,
        "recency_score": 88,
        "materiality_score": 85,
        "summary": "Short summary only.",
        "url": "https://example.com/news"
      }
    ],
    "news_count": 12,
    "deduplicated_count": 8,
    "data_quality": {
      "status": "complete",
      "sources_used": ["MarketAux", "NewsData", "Finnhub"]
    }
  }
}
```
