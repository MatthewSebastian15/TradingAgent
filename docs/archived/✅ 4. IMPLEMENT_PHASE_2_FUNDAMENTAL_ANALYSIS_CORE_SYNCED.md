# PHASE 2 — Fundamental Analysis Core

## 1. Tujuan Phase 2

Phase 2 membangun inti analisis fundamental agar TradingAgent lebih dekat dengan workflow equity analyst.

Phase ini hanya boleh dimulai setelah Phase 1 selesai, yaitu setelah:

- Struktur tab final sudah stabil.
- Tab **Fundamental** sudah ada.
- Key Financial Highlights sudah pindah ke tab Fundamental.
- API response, frontend, mock data, HTML preview, dan PDF export sudah sinkron.

Fokus Phase 2 adalah memperluas tab **Fundamental** menjadi pusat analisis keuangan dan valuasi.

---

## 2. Hasil Akhir yang Harus Dicapai

Setelah Phase 2 selesai, tab **Fundamental** harus memiliki struktur berikut:

```text
Fundamental
├── Key Financial Highlights
├── Financial Trend Analysis
├── Valuation Multiples
├── Fair Value Range
├── Bull / Base / Bear Scenario
├── Quality of Earnings
├── Balance Sheet Risk
├── Dividend Quality
└── Peer Comparison
```

Peer Comparison boleh dikerjakan paling akhir dalam fase ini karena kompleksitas multi-ticker lebih tinggi. Jangan mendahulukan peer comparison sebelum single-company fundamental stabil. Itu seperti memasang spoiler mobil sebelum mesinnya hidup.

# 6. Detail Feature 1 — Financial Trend Analysis YoY / QoQ

## 6.1 Tujuan

Menampilkan perkembangan keuangan perusahaan dari beberapa periode.

Tujuan utama:

- Melihat tren revenue.
- Melihat margin naik atau turun.
- Melihat net profit growth.
- Melihat ROE, EPS, BVPS, dan DER secara historis.
- Membantu user melihat apakah perusahaan membaik, stagnan, atau memburuk.

## 6.2 Period Logic

Gunakan logic periode yang konsisten.

Contoh:

| Waktu Analisis | Periode yang Ditampilkan |
|---|---|
| Q1 2026 | FY2022, FY2023, FY2024, FY2025 |
| Q2 2026 | FY2023, FY2024, FY2025, FY2026Q1 |
| Q4 2025 | FY2022, FY2023, FY2024, FY2025Q1, FY2025Q2, FY2025Q3 |
| Q3 2025 | FY2022, FY2023, FY2024, FY2025Q1, FY2025Q2 |

Aturan:

1. Jika full-year terbaru tersedia, tampilkan FY.
2. Jika full-year terbaru belum tersedia, tampilkan quarter terakhir.
3. Jangan mencampur periode yang tidak jelas.
4. Jika vendor hanya memberi annual data, tampilkan annual-only mode.
5. Jika quarterly data kosong, jangan crash.

## 6.3 Metrics yang Harus Dihitung

| Metric | Formula |
|---|---|
| Revenue Growth % | `(revenue_current - revenue_previous) / revenue_previous * 100` |
| EBITDA Margin % | `EBITDA / Revenue * 100` |
| Net Profit Growth % | `(net_profit_current - net_profit_previous) / net_profit_previous * 100` |
| Net Profit Margin % | `Net Profit / Revenue * 100` |
| ROE % | `Net Income / Total Equity * 100` |
| EPS | `Net Income / Shares Outstanding` |
| BVPS | `Total Equity / Shares Outstanding` |
| DER | `Total Debt / Total Equity` |

# 7. Detail Feature 2 — Valuation Multiples

## 7.1 Tujuan

Menghitung valuation ratio agar user bisa menilai apakah saham murah, mahal, atau wajar.

## 7.2 Metrics

| Metric | Formula |
|---|---|
| P/E | `Market Cap / Net Income` atau `Price / EPS` |
| P/BV | `Market Cap / Total Equity` atau `Price / BVPS` |
| P/S | `Market Cap / Revenue` |
| EV | `Market Cap + Total Debt - Cash` |
| EV/EBITDA | `Enterprise Value / EBITDA` |

## 7.3 Handling Missing Data

| Missing Field | Fallback |
|---|---|
| EPS missing | Calculate from net income / shares outstanding |
| BVPS missing | Calculate from equity / shares outstanding |
| EBITDA missing | Estimate from operating income if available, with warning |
| Cash missing | EV can still be calculated as partial or return `N/A` |
| Debt missing | EV can still be calculated as partial or return `N/A` |
| Market cap missing | Use price * shares outstanding if both available |

## 7.4 Output Contract

```json
{
  "valuation_multiples": {
    "currency": "IDR",
    "market_cap": 125000000000000,
    "enterprise_value": 132000000000000,
    "pe": 12.5,
    "pbv": 1.8,
    "ps": 3.1,
    "ev_ebitda": 8.4,
    "interpretation": {
      "valuation_label": "fair",
      "main_reason": "P/E and P/BV are within reasonable range compared with profitability."
    },
    "data_quality": {
      "status": "partial",
      "fallback_used": ["EBITDA estimated from operating income"],
      "missing_fields": []
    }
  }
}
```

## 7.5 Frontend Requirements

| Requirement | Detail |
|---|---|
| Ratio format | P/E, P/BV, P/S, EV/EBITDA tampil dengan `x` |
| Label | Cheap / fair / expensive boleh ditampilkan jika logic tersedia |
| Warning | Jika EBITDA estimated, tampilkan catatan kecil |
| Jangan hardcode threshold | Threshold sebaiknya configurable atau documented |

# 8. Detail Feature 3 — Fair Value Range

## 8.1 Tujuan

Menghasilkan estimasi nilai wajar berbasis valuation.

## 8.2 Metode yang Bisa Dipakai

| Method | Data Required | Catatan |
|---|---|---|
| P/E based | EPS dan target P/E | Cocok untuk profitable company |
| P/BV based | BVPS dan target P/BV | Cocok untuk bank/financial |
| EV/EBITDA based | EBITDA, debt, cash, shares | Cocok untuk industrial/non-financial |
| P/S based | Revenue dan target P/S | Cocok jika laba belum stabil |

## 8.3 Basic Logic

```text
If sector is banking/financial:
    prioritize P/BV and ROE-based valuation
Else if EBITDA available:
    use EV/EBITDA
Else if EPS available:
    use P/E
Else:
    fallback to P/S or return N/A
```

## 8.4 Output Contract

```json
{
  "fair_value_range": {
    "currency": "IDR",
    "current_price": 9450,
    "bear": 8500,
    "base": 10200,
    "bull": 11800,
    "bear_upside_percent": -10.1,
    "base_upside_percent": 7.9,
    "bull_upside_percent": 24.9,
    "method": "multiple-based valuation",
    "primary_method": "P/BV",
    "assumptions": [
      "Base case uses normalized P/BV multiple",
      "Bear case assumes multiple compression",
      "Bull case assumes profitability improvement"
    ],
    "data_quality": {
      "status": "partial",
      "missing_fields": []
    }
  }
}
```

## 8.5 Frontend Requirements

| Requirement | Detail |
|---|---|
| Display range clearly | Bear, Base, Bull dalam 3 card atau table |
| Show current price | Agar upside/downside mudah dibandingkan |
| Show method | User harus tahu valuation memakai metode apa |
| Show assumptions | Jangan tampilkan fair value tanpa asumsi |

# Integrated Requirement — Key Financial Calculations in Phase 2

## 1. Why This Requirement Is Integrated Into Phase 2

The sectioned Key Financial Highlights UI and base contract are implemented in Phase 1.

Phase 2 must extend the calculation side because the same financial metrics are also used by:

- Financial Trend Analysis
- Valuation Multiples
- Fair Value Range
- Scenario Analysis
- Quality of Earnings
- Balance Sheet Risk
- Dividend Quality

This prevents duplicated formulas across modules. Apparently duplicated financial formulas are how numbers start disagreeing with themselves, which is impressive but useless.

---

## 2. Shared Financial Calculation Rules

Use a shared calculator module where possible.

Recommended file:

```text
backend/tradingagents-core/tradingagents/financial_highlights/calculator.py
```

or a shared fundamentals calculator if that better matches the project structure.

Required formulas:

| Metric | Formula |
|---|---|
| Revenue Growth (%) | `(Revenue current - Revenue previous) / Revenue previous * 100` |
| EBITDA Margin (%) | `EBITDA / Revenue * 100` |
| Net Profit Growth (%) | `(Net Profit current - Net Profit previous) / Net Profit previous * 100` |
| Net Profit Margin (%) | `Net Profit / Revenue * 100` |
| ROE (%) | `Net Profit / Average Equity * 100` or `Net Profit / Total Equity * 100` when average equity is unavailable |
| EPS | `Net Profit / Shares Outstanding` |
| BVPS | `Total Equity / Shares Outstanding` |
| DER | `Total Debt / Total Equity` |
| Dividend Yield (%) | `Dividend per Share / Reference Price * 100` |
| Payout Ratio (%) | `Dividend per Share / EPS * 100` |
| Free Cash Flow | `Operating Cash Flow - Capex` |
| CFO to Net Income | `Operating Cash Flow / Net Income` |
| Enterprise Value | `Market Cap + Total Debt - Cash` |
| P/E | `Market Cap / Net Income` or `Price / EPS` |
| P/BV | `Market Cap / Total Equity` or `Price / BVPS` |
| P/S | `Market Cap / Revenue` |
| EV/EBITDA | `Enterprise Value / EBITDA` |

---

## 3. Safe Calculation Helpers

Use safe helpers to avoid division by zero and missing value crashes.

```python
def safe_divide(numerator: float | None, denominator: float | None) -> float | None:
    if numerator is None or denominator in (None, 0):
        return None
    return numerator / denominator


def safe_percent(numerator: float | None, denominator: float | None) -> float | None:
    ratio = safe_divide(numerator, denominator)
    if ratio is None:
        return None
    return ratio * 100


def safe_growth_percent(current: float | None, previous: float | None) -> float | None:
    if current is None or previous in (None, 0):
        return None
    return ((current - previous) / previous) * 100


def calculate_payout_ratio(dividend_per_share: float | None, eps: float | None) -> float | None:
    return safe_percent(dividend_per_share, eps)
```
