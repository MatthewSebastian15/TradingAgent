# PHASE 4 — Risk / Data Quality, Source Confidence, Report Sync, dan Final Hardening

## 1. Tujuan Phase 4

Phase 4 adalah fase validasi akhir.

Fase ini menjawab dua pertanyaan penting:

1. Apa risiko utama dari saham ini?
2. Seberapa bisa dipercaya data yang digunakan untuk menghasilkan analisis?

Tanpa Phase 4, sistem bisa terlihat pintar tetapi tidak transparan. Itu berbahaya, karena software yang terlalu percaya diri dengan data bolong adalah bentuk modern dari ramalan warung kopi.

---

## 2. Hasil Akhir yang Harus Dicapai

Setelah Phase 4 selesai:

1. Tab **Risk / Data Quality** lengkap.
2. Risiko dari fundamental, market, technical, news, dan catalyst digabungkan.
3. Data quality score tersedia.
4. Vendor status terlihat.
5. Missing fields terlihat.
6. Fallback used terlihat.
7. Stale data warning tersedia.
8. Calculation notes tersedia.
9. HTML preview dan PDF export sudah sinkron penuh.
10. Mock data final lengkap.
11. End-to-end test berjalan untuk semua tab.

---

## 3. Prinsip Sinkronisasi Phase 4

| Prinsip | Detail |
|---|---|
| Risk harus aggregate dari fase sebelumnya | Risk tab membutuhkan output Phase 2 dan Phase 3. |
| Jangan hitung ulang sembarangan | Reuse `balance_sheet_risk`, `technical_entry`, `news_impact`, `scenario_analysis`. |
| Data quality harus transparan | Tampilkan vendor status, missing fields, fallback, stale warning. |
| Report harus final sync | HTML/PDF harus mengikuti struktur akhir. |
| Mock data harus complete | Semua field final harus ada dalam mock data. |
| No silent failure | Field kosong harus terlihat sebagai `N/A` atau warning. |
| Calculation notes wajib jelas | Formula penting harus bisa diaudit. |
| Risk bukan rekomendasi baru | Risk tab menjelaskan risiko, bukan mengganti final recommendation di tab Analisis. |

# 7. Detail Feature 1 — Risk Summary

## 7.1 Tujuan

Memberi ringkasan risiko utama dari semua module.

## 7.2 Input

| Source | Field |
|---|---|
| Fundamental | `balance_sheet_risk`, `quality_of_earnings`, `financial_trends` |
| Valuation | `fair_value_range`, `scenario_analysis` |
| Chart | `technical_entry`, `price_performance` |
| News | `news_impact`, `catalyst_tracker` |
| Data Quality | `source_confidence`, missing fields |

## 7.3 Risk Categories

| Category | Contoh Risiko |
|---|---|
| Financial Risk | DER tinggi, FCF lemah, margin turun |
| Valuation Risk | Current price jauh di atas base fair value |
| Market Risk | Volatility tinggi, drawdown besar |
| Technical Risk | Entry quality risky, price dekat resistance |
| News Risk | Negative catalyst, bad sentiment |
| Data Risk | Banyak missing fields atau vendor gagal |

## 7.4 Output Contract

```json
{
  "risk_summary": {
    "overall_risk": "moderate",
    "risk_score": 62,
    "main_risks": [
      "Margin pressure",
      "High volatility",
      "Weak free cash flow"
    ],
    "risk_flags": [
      "Watch margin trend",
      "Monitor debt level",
      "Avoid aggressive entry near resistance"
    ],
    "risk_explanation": "The stock has manageable balance sheet risk, but volatility and cash flow quality should be monitored."
  }
}
```

## 7.5 Risk Label Logic

| Score Range | Label |
|---|---|
| 0-30 | Low |
| 31-65 | Moderate |
| 66-100 | High |

Catatan: score bisa dibalik jika project memakai scoring health. Yang penting label dan formula konsisten.

# 9. Detail Feature 3 — Market Risk

## 9.1 Tujuan

Mengukur risiko pergerakan harga.

## 9.2 Metrics

| Metric | Formula |
|---|---|
| Volatility % | Standard deviation return annualized atau period-based sesuai config |
| Max Drawdown % | Peak-to-trough maximum decline |
| ATR | Average True Range |
| Price Range % | `(period_high - period_low) / period_low * 100` |
| Risk Bucket | Low / Medium / High |

## 9.3 Output Contract

```json
{
  "market_risk": {
    "volatility_percent": 24.5,
    "max_drawdown_percent": -18.2,
    "atr": 125,
    "price_range_percent": 12.8,
    "risk_bucket": "medium",
    "notes": [
      "Volatility is moderate compared with the selected window.",
      "Max drawdown remains within acceptable range."
    ]
  }
}
```

# 10. Detail Feature 4 — Risk-Adjusted Return

## 10.1 Tujuan

Membandingkan potensi return dengan risiko.

## 10.2 Input

| Input | Source |
|---|---|
| Current Price | Price chart / market data |
| Base Fair Value | Phase 2 Fair Value |
| Bear Fair Value | Phase 2 Fair Value |
| Stop Loss | Analysis action plan |
| Take Profit | Analysis action plan |
| Volatility | Market Risk |
| ATR | Technical Entry |

## 10.3 Metrics

| Metric | Formula |
|---|---|
| Upside % | `(target_or_base_value - current_price) / current_price * 100` |
| Downside % | `(current_price - stop_loss_or_bear_value) / current_price * 100` |
| Risk/Reward Ratio | `absolute(upside) / absolute(downside)` |
| Expected Return Label | Attractive / Balanced / Unattractive |

## 10.4 Output Contract

```json
{
  "risk_adjusted_return": {
    "upside_percent": 18.0,
    "downside_percent": -9.0,
    "risk_reward_ratio": "2.0x",
    "expected_return_label": "attractive",
    "notes": [
      "Upside potential is around twice the downside risk.",
      "Risk/reward remains attractive if stop loss discipline is followed."
    ]
  }
}
```

# 18. Detail Feature 12 — Calculation Notes

## 18.1 Tujuan

Menampilkan formula penting agar hasil bisa diaudit.

## 18.2 Formula Notes

| Formula | Note |
|---|---|
| Revenue Growth | `(current revenue - previous revenue) / previous revenue` |
| EBITDA Margin | `EBITDA / revenue` |
| Net Profit Margin | `net profit / revenue` |
| ROE | `net income / total equity` |
| EPS | `net income / shares outstanding` |
| BVPS | `total equity / shares outstanding` |
| DER | `total debt / total equity` |
| FCF | `operating cash flow - capex` |
| Enterprise Value | `market cap + total debt - cash` |
| P/E | `market cap / net income` |
| P/BV | `market cap / total equity` |
| EV/EBITDA | `enterprise value / EBITDA` |
| Risk/Reward | `expected upside / expected downside` |
| Max Drawdown | `largest peak-to-trough decline` |

## 18.3 Output Contract

```json
{
  "calculation_notes": [
    "Revenue Growth = (current revenue - previous revenue) / previous revenue",
    "DER = total debt / total equity",
    "FCF = operating cash flow - capital expenditure",
    "Enterprise Value = market cap + total debt - cash",
    "Risk/reward ratio = expected upside / expected downside"
  ]
}
```
