# PHASE 1 — Foundation, Tab Structure, Profil, dan Migrasi Key Financial Highlights

## 1. Tujuan Phase 1

Phase 1 adalah fondasi utama sebelum fitur equity analyst-level lain ditambahkan.

Fokus utama fase ini:

1. Menetapkan struktur tab final:
   ```text
   Analisis | Profil | Fundamental | Chart & Price | News | Risk / Data Quality
   ```
2. Membuat tab **Profil**.
3. Membuat tab **Fundamental**.
4. Memindahkan **Key Financial Highlights** yang sekarang ada ke tab **Fundamental**.
5. Menyamakan API response, mock data, HTML preview, PDF export, dan frontend agar tidak ada perbedaan struktur.
6. Membuat format angka finansial konsisten, termasuk mata uang, satuan, persen, dan rasio.

Phase ini belum fokus ke valuation lanjutan, scenario, technical indicator, atau risk dashboard. Itu dikerjakan di fase berikutnya. Jangan semua dimasukkan sekaligus, karena begitulah cara bug berkembang biak seperti jamur di musim hujan.

---

## 2. Hasil Akhir yang Harus Dicapai

Setelah Phase 1 selesai, aplikasi harus memiliki struktur tab berikut:

| Urutan | Nama Tab | Status Setelah Phase 1 |
|---|---|---|
| 1 | Analisis | Tetap ada dan dirapikan sebagai tab kesimpulan utama |
| 2 | Profil | Tab baru, berisi identitas dan informasi perusahaan |
| 3 | Fundamental | Tab baru, berisi Key Financial Highlights yang dipindahkan dari posisi lama |
| 4 | Chart & Price | Tetap ada, belum ditambah fitur teknikal lanjutan |
| 5 | News | Tetap ada, belum ditambah impact scoring |
| 6 | Risk / Data Quality | Placeholder atau tab dasar, detail penuh dikerjakan di Phase 4 |

| Prinsip | Detail Implementasi |

## 7.4 Backend Logic

Buat builder/normalizer:

```text
company_profile/profile_builder.py
```

Atau gunakan lokasi yang sesuai dengan struktur repo existing.

Flow backend:

```text
Input ticker
→ Fetch profile data from available vendors
→ Normalize field names
→ Apply vendor priority
→ Fill missing fields with null or N/A
→ Build data_quality object
→ Attach to final API response as company_profile
```

# 9. Detail Feature 4 — Move Key Financial Highlights to Fundamental Tab

## 9.1 Tujuan

Memindahkan section existing **Key Financial Highlights** ke dalam tab **Fundamental**.

## 9.2 Posisi di Tab Fundamental

Pada Phase 1, struktur awal tab Fundamental:

```text
Fundamental
└── Key Financial Highlights
```

Pada Phase 2, tab ini akan diperluas menjadi:

```text
Fundamental
├── Key Financial Highlights
├── Financial Trend Analysis
├── Valuation Multiples
├── Fair Value Range
├── Bull / Base / Bear Scenario
├── Quality of Earnings
├── Balance Sheet Risk
├── Dividend Quality
└── Peer Comparison
```

## 9.3 Field Wajib Key Financial Highlights

| Group | Metric | API Field | Format |
|---|---|---|---|
| Market | Market Cap | `market_cap` | Currency + unit |
| Revenue | Revenue | `revenue` | Currency + unit |
| Revenue | Revenue Growth | `revenue_growth_percent` | Percent |
| Profitability | EBITDA | `ebitda` | Currency + unit |
| Profitability | EBITDA Margin | `ebitda_margin_percent` | Percent |
| Profitability | Net Profit | `net_profit` | Currency + unit |
| Profitability | Net Profit Growth | `net_profit_growth_percent` | Percent |
| Profitability | Net Profit Margin | `net_profit_margin_percent` | Percent |
| Profitability | ROE | `roe_percent` | Percent |
| Per Share | EPS | `eps` | Currency per share |
| Per Share | BVPS | `bvps` | Currency per share |
| Leverage | DER | `der` | Ratio `x` |
| Profitability | Profit Margin | `profit_margin_percent` | Percent |
| Dividends | Dividend Yield | `dividend_yield_percent` | Percent |
| Dividends | Payout Ratio | `payout_ratio_percent` | Percent |

## 9.4 Unit Label Wajib

Di atas tabel harus ada label:

```text
Currency: IDR | Unit: Billion Rupiah unless stated otherwise
```

Jika currency bukan IDR, label menyesuaikan:

```text
Currency: USD | Unit: Million USD unless stated otherwise
```

## 9.5 Format Rules

| Jenis Data | Format |
|---|---|
| Currency + unit | `Rp 1,250 billion` atau `USD 1,250 million` |
| Percent | `12.5%` |
| Ratio | `0.65x` |
| EPS/BVPS | `Rp 250/share` |
| Missing value | `N/A` |
| Negative number | `-5.2%` atau `-Rp 120 billion` |
| Zero | `0`, `0.0%`, atau `0.00x` sesuai konteks |

## 9. Profit Margin Naming Rule

The requested metric `Profit Margin (%)` should map to `Net Profit Margin (%)`.

Use this final display label:

```text
Net Profit Margin / Profit Margin (%)
```

Reason:

```text
Profit Margin usually means Net Profit Margin in financial summary tables.
Showing both Net Profit Margin and Profit Margin as two separate rows would duplicate the same value and confuse users.
```

Do not create two duplicated rows unless a separate gross profit margin or operating profit margin is added later.

## 11. Numeric Percentage Convention

Store the raw numeric percentage as the human percentage value, not the decimal fraction.

Correct:

```json

  "value": 7.4,
  "display": "7.40%",
  "unit": "%"
}
```

Incorrect:

```json
{
  "value": 0.074,
  "display": "0.07%",
  "unit": "%"

```

If a vendor returns decimal ratio values, convert them before display:

```text

0.4433 -> 44.33%
```

## 14. Scale Conversion Rule

If the source value is in raw IDR, convert it to IDR billion:

```text
IDR billion = raw IDR / 1,000,000,000
```

If the source value is already in IDR million, convert it to IDR billion:

```text
IDR billion = IDR million / 1,000
```

If the source value is already in IDR billion, do not convert again.

The parser must track or infer source units carefully. Do not divide twice.

## 19. Formatter Rules

```python
from __future__ import annotations


def format_number(value: float | None, decimals: int = 2) -> str:
    if value is None:
        return "N/A"
    return f"{value:,.{decimals}f}"


def format_currency_scaled(value: float | None, decimals: int = 1) -> str:
    if value is None:
        return "N/A"
    return f"{value:,.{decimals}f}"


def format_percent(value: float | None, decimals: int = 2) -> str:
    if value is None:
        return "N/A"
    return f"{value:,.{decimals}f}%"


def format_ratio(value: float | None, decimals: int = 2) -> str:
    if value is None:
        return "N/A"
    return f"{value:,.{decimals}f}x"


def format_per_share(value: float | None, decimals: int = 2) -> str:
    if value is None:
        return "N/A"
    return f"{value:,.{decimals}f}"


def format_financial_value(value: float | None, format_type: str) -> str:
    if value is None:
        return "N/A"

    if format_type == "currency_scaled":
        return format_currency_scaled(value, decimals=1)
    if format_type == "percent":
        return format_percent(value, decimals=2)
    if format_type == "ratio":
        return format_ratio(value, decimals=2)
    if format_type == "per_share":
        return format_per_share(value, decimals=2)

    return format_number(value, decimals=2)
```

Required formatting behavior:

| `currency_scaled` | `124193.8` | `124,193.8` |

| `percent` | `44.33` | `44.33%` |
| `ratio` | `0.51` | `0.51x` |
| `per_share` | `589.93` | `589.93` |
| any | `None` | `N/A` |
