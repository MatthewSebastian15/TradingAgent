# IMPLEMENT EXISTING POSITION ACTION SYNC

## 1. Tujuan Perbaikan

Dokumen ini menjelaskan implementasi sinkronisasi antara status **EXISTING POSITION** dengan field berikut:

1. **REBALANCING ACTION**
2. **POSITION ACTION**
3. **NEW ENTRY ACTION**
4. **POSITION SIZE HINT**

Tujuan utamanya adalah memastikan output analisis tidak memberikan instruksi yang bertentangan. Contoh masalah yang harus dihindari:

- User **tidak punya posisi**, tetapi sistem menampilkan `Trim position` atau `Exit position`.
- User **sudah punya posisi**, tetapi sistem menampilkan `Open new position` seolah-olah belum ada posisi.
- User **sudah punya posisi**, tetapi `NEW ENTRY ACTION` masih menampilkan bahasa entry baru yang membingungkan.
- `POSITION SIZE HINT` masih terlalu generik dan tidak membedakan antara entry baru, tambah posisi, tahan posisi, kurangi posisi, atau keluar posisi.

Perbaikan ini harus menjadikan `has_existing_position`, `position_quantity`, dan `average_entry_price` sebagai konteks utama dalam menentukan action yang ditampilkan ke user.

## 3. Masalah Saat Ini

Berdasarkan struktur saat ini, logic utama sudah memiliki `normalize_rebalancing_action()` dan sebagian matrix dasar. Namun masih ada beberapa masalah:

### 3.1 Existing Position Masih Bergantung pada Boolean Mentah

Saat ini logic utama menggunakan:

```python
bool(has_existing_position)
```

Masalahnya, input user bisa saja tidak konsisten:

| Input | Masalah |
|---|---|
| `has_existing_position=false`, `position_quantity=100` | Sistem bisa menganggap user tidak punya posisi, padahal quantity menunjukkan ada posisi. |
| `has_existing_position=true`, `position_quantity=0` | Sistem bisa menganggap user punya posisi, padahal quantity nol. |
| `has_existing_position=true`, `position_quantity=None` | Sistem harus tetap anggap punya posisi, tapi quantity tidak diketahui. |

Karena itu harus ada helper khusus untuk menentukan status existing position final.

---

### 3.2 New Entry Action Belum Kontekstual untuk Existing Position

Logic saat ini secara konsep masih seperti ini:

```python
elif has_existing_position:
    decision.position_action = decision.rebalancing_action
    decision.new_entry_action = (
        "Wait for better entry" if final_decision in ACTIONABLE_DECISIONS else "No new entry"
    )
```

Masalahnya:

- Kalau user punya posisi dan decision `Buy`, output `Wait for better entry` bisa membingungkan.
- Kalau user punya posisi dan action sebenarnya `Add position`, harus dijelaskan bahwa itu **add to existing position**, bukan entry baru yang terpisah.
- Kalau user punya posisi dan decision `Sell`, `NEW ENTRY ACTION` harus menegaskan bahwa tidak ada entry baru dan fokusnya adalah trim/exit.

---

### 3.3 Position Size Hint Masih Terlalu Generik

Saat ini hint berbasis volatility seperti:

```python

```

Contoh:

```text
Use standard risk management and avoid oversized position.
```

Masalahnya, kalimat ini belum menjawab konteks user:

| Status User | Kebutuhan Hint |
|---|---|
| Tidak punya posisi | Starter size untuk entry baru. |
| Sudah punya posisi + Add | Ukuran tambahan posisi. |
| Sudah punya posisi + Maintain | Tidak tambah exposure. |
| Sudah punya posisi + Trim | Kurangi exposure. |

Perbaikan harus memastikan sebelum return, field berikut tetap diisi konsisten:


## 4. Kontrak Final Field

### 4.1 EXISTING POSITION

Status existing position final harus ditentukan dari kombinasi:

```python
has_existing_position
position_quantity
average_entry_price
```

Prioritas paling kuat adalah `position_quantity` jika tersedia.

| Kondisi | Status Final |
|---|---|
| `position_quantity > 0` | Punya posisi |
| `position_quantity == 0` | Tidak punya posisi |
| `position_quantity < 0` | Anggap tidak valid untuk long-only portfolio, fallback ke `has_existing_position` atau set warning |
| `position_quantity is None` dan `has_existing_position=True` | Punya posisi, quantity tidak diketahui |
| `position_quantity is None` dan `has_existing_position=False` | Tidak punya posisi |

Rekomendasi:

```python
resolved_has_existing_position = resolve_existing_position(
    has_existing_position=has_existing_position,
    position_quantity=position_quantity,
)
```

---

### 4.2 REBALANCING ACTION

Allowed values yang sudah ada:

```text
Open new position
Add position
Maintain position
Trim position
Exit position
Avoid new entry
```

Rule berdasarkan status existing position:

| Status User | Allowed Rebalancing Action |
|---|---|
| Tidak punya posisi | `Open new position`, `Avoid new entry` |
| Sudah punya posisi | `Add position`, `Maintain position`, `Trim position`, `Exit position` |

Tidak boleh ada crossing seperti ini:

| Status User | Action yang Tidak Boleh Muncul |
|---|---|
| Tidak punya posisi | `Add position`, `Maintain position`, `Trim position`, `Exit position` |
| Sudah punya posisi | `Open new position`, `Avoid new entry` sebagai portfolio action utama |

Catatan: Untuk existing position, `Avoid new entry` boleh muncul di `NEW ENTRY ACTION`, tetapi jangan menjadi `REBALANCING ACTION` utama karena user sudah punya posisi yang harus dikelola.

---

### 4.3 POSITION ACTION

`POSITION ACTION` hanya berlaku jika user sudah punya posisi.

| Existing Position | Position Action |
|---|---|
| Tidak punya posisi | `None` |
| Punya posisi | Sama dengan `rebalancing_action` |

Allowed values untuk user yang punya posisi:

```text
Add position
Maintain position
Trim position
Exit position
```

Tidak boleh menggunakan:

```text
Open new position
Avoid new entry
```

untuk `position_action`.

---

### 4.4 NEW ENTRY ACTION

`NEW ENTRY ACTION` menjawab pertanyaan:

> Apakah user boleh membuka exposure baru?

Untuk user yang **tidak punya posisi**, field ini adalah instruksi entry baru.

Untuk user yang **sudah punya posisi**, field ini harus menjelaskan bahwa tidak ada entry baru terpisah. Fokusnya adalah mengelola posisi yang sudah ada.

#### Allowed Output untuk User Tanpa Posisi

| Kondisi | New Entry Action |
|---|---|
| Buy valid | `Allowed with validated entry` |
| Buy tapi trade plan invalid | `Wait for better entry` |
| Hold | `No new entry` |
| Sell | `Avoid new entry` |
| Missing price | `No new entry until price data is valid` |

#### Allowed Output untuk User dengan Existing Position

| Rebalancing Action | New Entry Action |
|---|---|
| `Add position` | `No separate new entry; add only to existing position` |
| `Maintain position` | `No new entry; maintain existing position` |
| `Trim position` | `No new entry; reduce existing exposure` |
| `Exit position` | `No new entry; exit existing position` |
| Missing price | `No new entry until price data is valid` |

### 6.1 Resolve Existing Position

```python
def resolve_existing_position(
    has_existing_position: bool | None,
    position_quantity: float | None,
) -> bool:
    """Resolve final existing-position status from request flag and quantity.

    Quantity is stronger than the boolean flag when it is explicitly provided.
    """
    if position_quantity is not None:
        try:
            quantity = float(position_quantity)
        except (TypeError, ValueError):
            return bool(has_existing_position)

        if quantity > 0:
            return True
        if quantity == 0:
            return False

        # Negative quantity is not supported for long-only portfolio.
        # Fall back to explicit boolean instead of treating it as existing long position.
        return bool(has_existing_position)

    return bool(has_existing_position)
```

### 6.2 Position Action Helper

```python
def build_position_action(
    has_existing_position: bool,
    rebalancing_action: str | None,
) -> str | None:
    """Return position action only when the user already owns the position."""
    if not has_existing_position:
        return None

    if rebalancing_action in {
        "Add position",
        "Maintain position",
        "Trim position",
        "Exit position",
    }:
        return rebalancing_action

    return "Maintain position"
```

Reasoning:

- Kalau user tidak punya posisi, `position_action` harus `None`.
- Kalau user punya posisi, action harus berada dalam konteks existing position.
- Kalau ada value tidak valid, fallback aman adalah `Maintain position`.

### 6.3 New Entry Action Helper

```python
def build_new_entry_action(
    *,
    has_existing_position: bool,
    final_decision: str | None,
    rebalancing_action: str | None,
    trade_plan_valid: bool,
    current_price_ok: bool,
) -> str:
    """Return user-facing new-entry instruction synced with existing position."""
    if not current_price_ok:
        return "No new entry until price data is valid"

    normalized_decision = _canonical_decision(final_decision)

    if has_existing_position:
        if rebalancing_action == "Add position":
            return "No separate new entry; add only to existing position"
        if rebalancing_action == "Maintain position":
            return "No new entry; maintain existing position"
        if rebalancing_action == "Trim position":
            return "No new entry; reduce existing exposure"
        if rebalancing_action == "Exit position":
            return "No new entry; exit existing position"
        return "No new entry; maintain existing position"

    if normalized_decision == "Buy" and trade_plan_valid:
        return "Allowed with validated entry"
    if normalized_decision == "Buy":
        return "Wait for better entry"
    if normalized_decision == "Sell":
        return "Avoid new entry"
    return "No new entry"
```

### 6.4 Position Size Hint Helper

```python
def build_position_size_hint(
    *,
    has_existing_position: bool,
    final_decision: str | None,
    rebalancing_action: str | None,
    volatility_level: str,
    trade_plan_valid: bool,
    current_price_ok: bool,
) -> str:
    """Return position-size guidance that matches user position context."""
    if not current_price_ok:
        if has_existing_position:
            return "Maintain current position size until valid price data is available."
        return "No new position suggested until valid price data is available."

    normalized_decision = _canonical_decision(final_decision)

    if has_existing_position:
        if rebalancing_action == "Add position":
            return {
                "Low": "Add to existing position gradually; normal add size may be acceptable.",
                "Medium": "Add gradually using standard risk limits.",
                "High": "Add only small size due to high volatility.",
                "Very High": "Avoid aggressive add; use very small add only if conviction remains strong.",
            }.get(volatility_level, "Add gradually using standard risk limits.")

        if rebalancing_action == "Maintain position":
            return "Maintain current position size; no additional exposure suggested."

        if rebalancing_action == "Trim position":
            return {
                "Low": "Trim part of the position to reduce exposure.",
                "Medium": "Trim part of the position to reduce exposure.",
                "High": "Trim position more conservatively due to elevated volatility.",
                "Very High": "Reduce exposure aggressively or prepare full exit if risk worsens.",
            }.get(volatility_level, "Trim part of the position to reduce exposure.")

        if rebalancing_action == "Exit position":
            return "Exit existing position; no new exposure suggested."

        return "Maintain current position size; no additional exposure suggested."

    if normalized_decision == "Buy" and trade_plan_valid:
        return {
            "Low": "New entry may use normal starter size if the trade plan is valid.",
            "Medium": "Use standard starter size and avoid oversized entry.",
            "High": "Use smaller starter size due to high volatility.",
            "Very High": "Use very small starter size only, or avoid entry if risk is not acceptable.",
        }.get(volatility_level, "Use standard starter size and avoid oversized entry.")

    if normalized_decision == "Buy":
        return "No new position suggested until the trade plan is valid."

    return "No new position suggested."
```

## 18. Kesimpulan

Perbaikan ini membuat action output lebih konsisten berdasarkan status posisi user.

Hasil akhir yang harus dijaga:

1. User tanpa posisi hanya mendapat `Open new position` atau `Avoid new entry` sebagai rebalancing.
2. User dengan existing position hanya mendapat `Add position`, `Maintain position`, `Trim position`, atau `Exit position` sebagai rebalancing.
3. `POSITION ACTION` hanya aktif untuk existing position.
4. `NEW ENTRY ACTION` tidak lagi ambigu antara entry baru dan add existing position.
5. `POSITION SIZE HINT` berubah dari generic volatility hint menjadi contextual sizing hint.
6. Missing price tetap menghasilkan output yang aman dan konsisten.

Dengan ini, dashboard tidak lagi memberi instruksi seperti menyuruh user exit dari posisi yang tidak pernah mereka punya. Sebuah kemajuan kecil bagi peradaban software finansial.
